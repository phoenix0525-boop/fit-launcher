# 螢幕適應、順暢度與程式邏輯審查（Claude，2026-10-26）

基礎：`codex/voice-google-navigation`（`f21cae6`，0.4.0）。本分支：`claude/adaptive-smooth`。
本審查未在 AKZ ZX09 實機或 Android 編譯環境執行；以 Kotlin 編譯器跑純邏輯單元測試，Android 測試交由 GitHub Actions。

## 參考的車機桌面做法

| 參考 | 做法 | 本專案採用 |
|---|---|---|
| Android Auto（Coolwalk 版面） | 依螢幕比例切換：寬螢幕地圖＋側欄卡片；超寬螢幕多欄；直向螢幕地圖在上、卡片在下 | `AdaptiveLayout`：兩欄／三欄／上下堆疊 |
| 一般副廠車機桌面（AGAMA、CarWebGuru 類） | 小螢幕精簡狀態列、大按鈕、固定底部或側邊操作 | 小螢幕精簡狀態列、按鈕縮小內距但維持 56 dp 高 |
| FYT 原廠桌面 Launcher3 | 常駐主畫面、返回時不重建；原廠 App 捷徑 | 主畫面常駐不重建地圖 |
| 開車趣 | Release 縮減、單一 Activity 內切換畫面 | 畫面切換淡入淡出、背景載入清單 |

## 發現與處理

| # | 類型 | 問題 | 處理 |
|---|---|---|---|
| 1 | 順暢度（嚴重） | 進入設定／所有 App 再返回時，主畫面被移出組合，MapLibre 地圖 `onDestroy` 後重建、重新下載樣式，返回桌面會白屏或延遲 | 主畫面常駐，其他畫面以覆蓋層顯示（淡入 160 ms／淡出 120 ms），覆蓋層攔截觸控並隱藏底層無障礙節點 |
| 2 | 順暢度（嚴重） | 每次切換畫面都在主執行緒重讀所有 App 與圖示（`loadIcon`），App 多時開「所有 App」會卡 | `AppCatalog` 背景執行緒載入並快取；安裝／移除／更新 App 或回到桌面超過 30 秒才重讀 |
| 3 | 順暢度 | 時鐘只顯示到分鐘卻每秒重組，每次重建 `SimpleDateFormat` | 對齊整分更新、格式器快取 |
| 4 | 順暢度 | 播放進度每 0.5 秒重組，但只顯示到秒；暫停時仍高頻更新 | 播放中對齊下一秒、暫停時每秒一次 |
| 5 | 螢幕適應（嚴重） | 主畫面固定左右 6.5:3.5、狀態列時鐘固定 240 dp：1024×600、1280×720@240dpi 狀態列擠壓，直向螢幕完全不適用 | 依 dp 尺寸自動選版面；小螢幕精簡狀態列、隱藏位置卡、縮小間距；短螢幕隱藏封面 |
| 6 | 螢幕適應 | 設定與實機檢測左側分類固定 240–260 dp，窄螢幕內容被壓縮 | 共用 `SectionNavLayout`：窄／直向改上方分頁列 |
| 7 | 螢幕適應 | 亮度時段列在窄畫面滑桿被擠到無法操作 | 640 dp 以下分兩行 |
| 8 | 測試 | 版面測試只涵蓋 2000×1200 | 新增六種尺寸（含 125% 字體）裁字測試與截圖 |

## 尚未處理（建議下一輪）

- 實機檢測的 `AutoChecks.run` 仍在主執行緒呼叫 `launchableApps`；建議改用 `AppCatalog` 或移到背景。
- 設定頁 `SettingsData` 的系統查詢在主執行緒；可改 `produceState`＋IO。
- 覆蓋層開啟時地圖仍在背後；可暫停 MapView 以省電（需實機量測）。
- `MainActivity` 超過 500 行，畫面狀態、語音、導航混在一起；建議拆出畫面狀態與動作處理。
- Android for Cars 設計準則建議觸控目標約 76 dp；目前多數按鈕 56 dp，播放鍵 56 dp。待實機確認可讀性後再決定是否放大。
- `claude/v0.3-improvements` 的原廠車機 App 入口、導航王通知轉彎、回家／去公司尚未在本線；依專案規則不自行合併，需使用者決定。
