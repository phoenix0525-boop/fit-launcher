# 0.4.23 單次系統目前音量測試

依0.4.22實車報告，桌面setStreamVolume/adjustStreamVolume目標35均仍讀36；方向盤降低實際聲音時Android六流未變。使用者已確認方向盤功能都正常，先前手動有問題是勾錯。小芳0/36切換伴隨播放活動改變，不能當原廠音量刻度。桌面實際音量問題尚未修復。

## 這次只需要測新項目
1. 停車、播放同一首音樂，先用方向盤設舒適音量。結束通話、等待語音助手/導航播報結束。
2. 設定 → 實機檢測 → 音量檢測 → 「系統目前音量：降低一次」。只按一次，等結果，不混用方向盤或小芳。
3. 回報有變小／沒有變化／不確定；再到匯出報告存文字檔。若新方法沒有作用，不重複按舊兩種方法。
每次只送一個降低請求，不會自動調回；需要時用方向盤調回。沒有音樂活動、非一般音訊模式、固定音量或Android媒體數值最低時不送。這是實驗檢測，不能保證效果，不會自動接到主畫面音量按鈕或滑桿。

## 方法與限制
公開AudioManager.adjustVolume(ADJUST_LOWER, FLAG_SHOW_UI)由Android選擇最相關音量通道，與先前固定STREAM_MUSIC測試分開；不是硬體按鍵注入，不保證與方向盤或小芳同一路徑，仍可能受到相同底層限制。
報告記錄是否曾嘗試請求、前/約150/600/1500ms取樣與六種流的isStreamMute。播放活動或音訊模式有變會標干擾，不將0/36當連續音量刻度；旗標也不能證明干擾原因。數值未變仍不能單憑此否定原廠實際聲音，須另看使用者回報。
不錄音，不讀小芳語音內容，不猜MCU/FYT，不新增私有介面、ADB或root權限，不修改方向盤與小芳。
舊四種檢測保留供歷史對照，本輪不用重做。使用者可自行把手動「方向盤有問題」誤勾更正為正常；程式不會自行改寫實機驗收結果。
