# FIT 桌面 v0.2 功能整合實作計畫

- 依據：`功能整合規格_2026-10-25_草案.md`（使用者已於 2026-10-25 核准）
- 執行原則：每個任務先測試、後實作；通過測試與建置後才提交下一個增量。

## 架構決定

- 現有 `tw.fitcar.launcher` 為唯一主程式；第三方 APK 只作功能比較。
- 從 GitHub 主分支建立新的受 Git 管理工作副本，再帶入目前本機 v0.1.1 的簽章設定；原資料夾不覆寫。
- 平台基線為 minSdk 31、compileSdk／targetSdk 36。
- 敏感功能分成獨立模組並預設關閉；拒絕權限不影響 Home 桌面。
- 測速資料採資料來源介面＋本機快取，演算法保持純 Kotlin，方便單元測試。

## 任務清單

### 第一階段：平台與簽章基線

#### 任務 1：建立 v0.2 受控工作副本

**驗收條件：**
- 工作副本保留 Git 歷史並對應 GitHub 主分支。
- 本機 v0.1.1 與遠端差異逐項帶入，原始資料夾不被修改。
- `.gitignore` 排除憑證、Base64、密碼與本機設定。

**驗證：** `git status`、秘密檔案搜尋、來源差異報告。

#### 任務 2：先寫平台與發行設定檢查

**驗收條件：**
- 測試／靜態檢查能驗證 minSdk 31、targetSdk 36、version 0.2.0。
- 能驗證 Manifest 不含 `QUERY_ALL_PACKAGES`、`REQUEST_INSTALL_PACKAGES`。
- 修改設定前檢查必須失敗。

**驗證：** 執行檢查並保存 RED 結果。

#### 任務 3：遷移 Android 12+／API 36

**驗收條件：**
- `minSdk = 31`、`compileSdk = 36`、`targetSdk = 36`。
- `versionCode = 3`、`versionName = 0.2.0`。
- 既有功能原始碼仍可編譯。

**驗證：** 任務 2 檢查轉為通過、`testDebugUnitTest`、`assembleDebug`。

#### 任務 4：正式 APK／AAB 簽章管線

**驗收條件：**
- Release APK 與 AAB 使用既有 `fitlauncher` 憑證。
- GitHub Secrets 未設定時不誤用 debug 金鑰。
- 產物可驗證套件、版本、簽章與非 debuggable。

**驗證：** `bundleRelease`、`assembleRelease`、`apksigner verify`、憑證指紋比對。

### 檢查點 A

- 全部單元測試通過。
- Debug APK、Release APK、Release AAB 建置成功。
- Git diff 不含任何金鑰、Base64 或密碼。
- 建置成功只標示為電腦／CI 驗證，不宣稱車機實測。

### 第二階段：固定測速垂直切片

#### 任務 5：測速領域模型與解析器

- 先寫錯誤欄位、座標範圍、速限與檔案大小測試。
- 實作政府 CSV／JSON 正規化模型，不連 UI。

#### 任務 6：前方測速判定引擎

- 先寫距離、方位、定位精度、去重與冷卻時間測試。
- 實作純 Kotlin 判定引擎。

#### 任務 7：資料快取與更新狀態

- 加入 HTTPS allowlist、逾時、大小上限、原子寫入及資料日期。
- 網路失敗保留最後一份有效資料。

#### 任務 8：GPS 前景服務與主畫面卡片

- 功能預設關閉，使用者主動啟用後才要求通知／位置權限。
- 顯示未授權、未定位、資料未載入、運作中與暫停狀態。

#### 任務 9：提示音與 TTS

- 使用者可分別關閉畫面、音效與朗讀。
- 同一測速點不得連續重複播報。

### 檢查點 B

- 模擬路線測試通過。
- 無資料、定位不準或資料格式錯誤時不產生假警示。
- 權限拒絕後 Home、KKBOX、導航、捷徑與亮度仍可使用。

### 第三階段：語音與路況

#### 任務 10：白名單語音命令解析器

- 先測試允許／未知／含糊命令，再接 Android SpeechRecognizer。

#### 任務 11：按鍵式語音 UI 與權限退路

- 只有按下按鈕時收音，不背景錄音。

#### 任務 12：官方國道路況介面驗證與適配器

- 確認授權、認證、速率與欄位後才寫正式連線。
- 未取得合法介面時保留停用狀態，不放示意事故。

### 最終檢查點

- 自動測試、建置、簽章與秘密掃描通過。
- 隱私權政策、資料來源及權限用途與實際程式一致。
- 車機在場後完成 Home、休眠喚醒、倒車、方向盤鍵、導航、GPS、雙指手勢實測。

## 主要風險

| 風險 | 等級 | 處理方式 |
|---|---|---|
| API 36 行為變更造成前景定位限制 | 高 | 第一階段先編譯與權限稽核，服務採正式 foreground service type |
| 政府資料格式或下載網址變動 | 高 | 解析器嚴格驗證、版本化快取、保留最後有效資料 |
| Google Play 對背景定位／前景服務審查 | 高 | 預設關閉、明確核心用途、最小權限、內部測試先行 |
| 金鑰遺失或外洩 | 高 | 不進 Git／產物，保留離線備份，CI 只用 Secrets |
| 車機 OEM 行為與標準 Android 不同 | 高 | 所有 OEM 相關能力維持條件式，必須實機驗證 |
